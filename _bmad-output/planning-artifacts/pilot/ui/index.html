หน้าจอ Pilot: ตั้งค่าคลัง ตำแหน่ง และผังคลัง

Prototype แบบคลิกได้ของ 11 story ใน pilot ใช้ token และ pattern จาก DESIGN.md และ EXPERIENCE.md ตรงตามที่กำหนด ข้อมูลเป็นตัวอย่างและเก็บใน browser tab นี้เท่านั้น ปุ่ม "ดูสถานะหน้าจอ (prototype)" ที่มุมล่างใช้สลับ state ต่างๆ และไม่ได้เป็นส่วนหนึ่งของ UI จริง

เส้นทาง demo

เข้าสู่ระบบ OTP เลือกคลัง คลังและโซน สร้างหลายตำแหน่ง พิมพ์ QR ตำแหน่ง ลงทะเบียนภาชนะ + พิมพ์ QR วาดผัง + ผูกตำแหน่ง + เผยแพร่ + ทดสอบเส้นทาง

รหัสผ่านตัวอย่าง zimple123 · OTP 6 หลักใดก็ได้ (000000 = รหัสผิด) · ใส่รหัสผ่านผิด 3 ครั้งเพื่อดูสถานะถูกล็อก

ข้อตัดสินใจและ assumption ใน prototype

ต้องให้ทีมยืนยัน

  • D-2: หน้าจอทำตาม AC เดิม คือการปิดใช้คลังต้องผ่าน approval · ถ้าเลือกเลื่อน approval ออกไป ให้เปลี่ยน dialog เป็นการยืนยันธรรมดา
  • รหัสคลัง รหัสโซน และรหัสตำแหน่งแก้ไม่ได้หลังสร้าง เพราะใช้อ้างอิงใน label และเอกสาร · ข้อนี้ AC ไม่ได้ระบุไว้
  • ค่าของ "ประเภทห้อง" (ทั่วไป / ควบคุมอุณหภูมิ / ของมีค่า) และ "การผสมสินค้า" 3 แบบเป็นค่าตัวอย่าง · PRD ระบุแค่ชื่อ field
  • ตัวเลือก "รูปแบบลำดับการเดิน" (งูเลื้อย / ทางเดียว / ตามรหัส) เป็นค่าตัวอย่าง
  • "ตั้งค่าคลัง › คลังและตำแหน่ง" แบ่งเป็น 4 ส่วน (รวมผังคลัง) ด้วย segmented control เพราะไม่มีเมนูระดับที่ 4 ใน IA
  • D-4 / D-5: ผังใน prototype ใช้ SVG ที่เขียนเองและคำนวณเส้นทางใน browser · ระบบจริงรอ architecture ตัดสินใจเรื่อง library, data model และการ precompute ระยะทาง

ข้อจำกัดของ prototype

  • QR เป็นลวดลายตัวอย่าง สแกนไม่ได้ · ระบบจริงต้องใช้ QR encoder
  • การพิมพ์ใช้ browser print (D-3) · silent print ยังเป็น [ARCH-PENDING]
  • สต็อกของคลังเป็นตัวเลขตัวอย่าง · ใน pilot จริงยังไม่มี ledger จึงเป็น 0 ทุกคลัง
  • มีเฉพาะภาษาไทย · ปุ่ม English ยังทำงานไม่ได้
  • Excel ส่งออกเป็นไฟล์ .csv (UTF-8 BOM) ที่เปิดใน Excel ได้
  • ผังคลังแสดงความหนาแน่นสต็อก (Story 4.8) ยังไม่มีใน prototype เพราะต้องรอ stock ledger
