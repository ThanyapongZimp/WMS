### Flow ภาพรวมตั้งแต่ต้นจนจบ

เส้นทางของสินค้าหนึ่งชิ้น ตั้งแต่เจ้าของเริ่มใช้คลังจนถึงวางบิล ตารางในแต่ละหมวดด้านล่างคือรายละเอียดของแต่ละขั้นนี้

- เจ้าของสินค้าตั้งค่าเริ่มต้น: ลงทะเบียน SKU กล่อง และเชื่อมร้านค้าออนไลน์ผ่าน Client Portal ส่วนคลังตั้งอัตราค่าบริการให้เจ้าของรายนั้น
- แจ้งส่งของเข้า (ASN): เจ้าของแจ้งล่วงหน้าว่าจะส่งอะไรเข้ามา กี่ชิ้น วันไหน คลังจึงเตรียมคนและพื้นที่ได้
- รับเข้าและจัดเก็บ: พนักงานสแกนรับเทียบ ASN ทำ VAS ถ้ามี แล้วนำของไปเก็บตาม location ที่ระบบแนะนำ สต็อกขึ้นสถานะพร้อมขาย
- ออเดอร์เข้า: ออเดอร์จาก marketplace ไหลเข้าระบบอัตโนมัติ ระบบจองสต็อกให้ทันที
- หยิบ: ระบบรวมออเดอร์เป็นใบหยิบ (wave/batch) พนักงานถือ PDA เดินหยิบตามลำดับ location ถ้าเป็น batch ก็คัดแยกเข้าออเดอร์อีกที
- แพ็ค: ที่สถานีแพ็ค พนักงานสแกนเช็กของ ระบบแนะนำกล่อง พิมพ์ใบปะหน้า และทำ VAS ตอนแพ็คถ้ามี
- ส่งมอบขนส่ง: คัดแยกพัสดุลงกระสอบตามขนส่ง สแกนส่งมอบ ออกใบ manifest ให้คนขนส่งเซ็นรับ แล้วปิดวัน
- ขนส่งเอง (ถ้ามี): กรณีคลังมีรถเอง วางแผนเที่ยวรถ คนขับรับงานในแอปและยืนยันการส่ง (POD)
- หลังการขาย: ของตีกลับมารับตรวจ แล้วคืนสต็อกหรือแยกชำรุด ถ้าเสียหายเปิดเคลมกับขนส่ง และชดเชยเจ้าของถ้าคลังผิด
- วางบิล: ทุกกิจกรรมข้างบนถูกบันทึกเป็นรายการค่าบริการ สิ้นรอบรวมเป็นบิล เจ้าของดูบิลได้ใน Portal

**วิธีอ่านตาราง:** คอลัมน์ "ขั้น" เรียงตามลำดับที่ใช้งานจริงในหมวดนั้น (0 = หน้าภาพรวม, เลขเดียวกัน = ทำในขั้นเดียวกัน, a = ทางแยก, – = ข้อมูลตั้งต้น ไม่อยู่ใน flow) ส่วน User journey บอกว่าผู้ใช้มาถึงหน้านี้จากไหน ทำอะไร และไปต่อที่ไหน


### 1. ฝั่งคลัง — งานหลักตาม flow (Inbound → Handover)

ห้าโมดูลนี้คือเส้นทางของสินค้าตั้งแต่เข้าคลังจนส่งมอบให้ขนส่ง


#### 1.1 รับสินค้าเข้า (Inbound) — 9 หน้า

Flow: ASN → รับสินค้า (เว็บ/PDA) → VAS ถ้ามี → Putaway → ปิดใบรับ


| ขั้น | ฟีเจอร์ | ผู้ใช้หลัก | รายละเอียดฟีเจอร์ | User journey (มาจากไหน → ทำอะไร → ไปต่อที่ไหน) | ไฟล์ |
|---|---|---|---|---|---|
| 0 | ภาพรวมรับเข้า | หัวหน้าคลัง | Dashboard งานรับเข้าวันนี้ แสดงรถ/ล็อตที่จะเข้า ที่รับเสร็จ และที่ค้าง ใช้วางคนประจำลานรับ | เปิดต้นกะเพื่อดูว่ามีอะไรจะเข้า → กดเข้าไปที่ ASN หรืองานรับที่ค้าง | inbound |
| 1 | ใบแจ้งรับเข้าล่วงหน้า (ASN) | เจ้าของสินค้า, CS คลัง | ใบแจ้งว่าจะส่งสินค้าอะไร กี่ชิ้น วันไหน สร้างได้ทั้งจากฝั่งคลัง จาก Portal หรือแปลงจาก PO | เจ้าของสร้าง ASN → คลังเห็นในรายการรอรับ → ใช้เป็นตัวเทียบตอนรับสินค้า | inbound-expected, inbound-create-expected |
| 2 | รับสินค้า | พนักงานรับเข้า | สแกนบาร์โค้ดสินค้าเทียบกับ ASN ระบบนับยอดและเตือนเมื่อขาด/เกิน บันทึกล็อตและวันหมดอายุได้ | เลือก ASN → สแกนทีละกล่อง/ชิ้นบน PDA → ยืนยันยอด → ส่งต่อไป VAS หรือ Putaway | inbound-receive, inbound-pda-sample |
| 2a | ใบรับชั่วคราว | พนักงานรับเข้า, CS คลัง | รับของที่มาโดยไม่มี ASN หรือยอดไม่ตรง พักไว้ในสถานะรอยืนยันจนเจ้าของตอบ | ของมาไม่มี ASN → เปิดใบรับชั่วคราว → ส่งคำขอยืนยันถึงเจ้าของ → ยืนยันแล้วจึงรับเข้าจริง | inbound-temp-receipts |
| 3 | งานเพิ่มเติมตอนรับเข้า (VAS) | พนักงาน VAS | งานที่ต้องทำก่อนเก็บ เช่น ติดสติ๊กเกอร์บาร์โค้ด แบ่งแพ็ค ใส่ถุง คิดเป็นค่าบริการแยก | รับเสร็จ → ระบบสร้างงาน VAS ตามที่เจ้าของสั่ง → ทำเสร็จจึงไป Putaway | inbound-vas |
| 4 | จัดเก็บเข้าตำแหน่ง (Putaway) | พนักงานจัดเก็บ | ระบบแนะนำ location ตามกฎคลัง (โซน ประเภทสินค้า ที่ว่าง) พนักงานสแกน location ยืนยันการวาง | หยิบของจากลานรับ → สแกน location ที่แนะนำ → สต็อกเปลี่ยนเป็นพร้อมขาย | inbound-putaway |
| 5 | ใบรับสินค้า | หัวหน้าคลัง, เจ้าของสินค้า | ประวัติใบรับที่ปิดแล้ว พร้อมยอดจริงเทียบ ASN ใช้อ้างอิงเวลามีข้อโต้แย้งเรื่องจำนวน | หลังปิดงานรับ → ใช้ค้นย้อนหลังและเป็นฐานคิดค่ารับเข้า | inbound-receipts |


#### 1.2 คำสั่งซื้อ (Orders) — 5 หน้า

Flow: ออเดอร์เข้า (จาก marketplace/Portal) → จองสต็อก → ส่งเข้า Picking → ติดตามจนส่งถึง


| ขั้น | ฟีเจอร์ | ผู้ใช้หลัก | รายละเอียดฟีเจอร์ | User journey (มาจากไหน → ทำอะไร → ไปต่อที่ไหน) | ไฟล์ |
|---|---|---|---|---|---|
| 0 | ภาพรวมคำสั่งซื้อ | หัวหน้าคลัง, CS คลัง | สรุปจำนวนออเดอร์ตามสถานะ (รอหยิบ กำลังแพ็ค รอส่ง ส่งแล้ว) รวมทุกเจ้าของ เห็นออเดอร์ที่เสี่ยงหลุด cut-off | เปิดดูภาพรวม → กดสถานะที่ผิดปกติเพื่อเข้าไปดูรายการ | orders |
| 1 | รายการคำสั่งซื้อ | CS คลัง | ตารางออเดอร์ทั้งหมด ค้นหาและกรองตามสถานะ ช่องทางขาย และเจ้าของ | ออเดอร์ไหลเข้าจากการเชื่อมต่อ → ค้นหา/กรอง → เปิดรายละเอียดรายออเดอร์ | orders-list |
| 2 | รายละเอียดคำสั่งซื้อ | CS คลัง, เจ้าของสินค้า | ข้อมูลออเดอร์ รายการสินค้า และ timeline ทุกสถานะตั้งแต่รับออเดอร์จนส่งถึงลูกค้า | เปิดจากรายการ → ดูว่าติดอยู่ขั้นไหน → ตามงานกับทีมที่เกี่ยวข้อง | orders-detail, orders-detail-delivered |
| 3 | เคลม / ส่งซ้ำ | CS คลัง | จากออเดอร์ที่มีปัญหา เปิดเคลมและสร้างออเดอร์ส่งซ้ำได้ทันทีโดยไม่ต้องคีย์ใหม่ | ลูกค้าแจ้งของผิด/เสียหาย → เปิดเคลมจากออเดอร์ → สร้างออเดอร์ส่งซ้ำ → เคลมไปต่อที่โมดูล Claims | orders-detail-claim-resend |


#### 1.3 หยิบสินค้า (Picking) — 10 หน้า

Flow: ตั้งกฎ → สร้างใบหยิบ (เอง/อัตโนมัติ) → หยิบบน PDA → จัดการของขาด → คัดแยก → ส่งแพ็ค


| ขั้น | ฟีเจอร์ | ผู้ใช้หลัก | รายละเอียดฟีเจอร์ | User journey (มาจากไหน → ทำอะไร → ไปต่อที่ไหน) | ไฟล์ |
|---|---|---|---|---|---|
| 0 | ภาพรวมการหยิบ | หัวหน้าคลัง | งานหยิบที่ค้าง กำลังทำ และเสร็จแล้ว พร้อมความเร็วการหยิบ ใช้ย้ายคนไปจุดที่คอขวด | ดูระหว่างกะ → เข้าใบหยิบที่ช้าหรือมีปัญหา | picking |
| 1 | กฎการหยิบ | หัวหน้าคลัง, Admin | ตั้งว่าจะหยิบล็อตไหนก่อน (FIFO/FEFO) เรียงลำดับ location อย่างไร และรวมออเดอร์แบบไหน | ตั้งครั้งเดียว → ระบบใช้ทุกครั้งที่สร้างใบหยิบ | picking-pick-rules |
| 2 | สร้างใบหยิบเอง | หัวหน้าคลัง | เลือกออเดอร์มารวมเป็น wave/batch ด้วยมือ เช่น รวมออเดอร์ด่วนหรือของชิ้นเดียว | เลือกออเดอร์จากคิว → สร้างใบหยิบ → มอบหมายให้พนักงาน | picking-create |
| 2 | สร้างใบหยิบอัตโนมัติ | หัวหน้าคลัง | ตั้งเวลาหรือเงื่อนไขให้ระบบสร้างใบหยิบเอง เช่น ทุก 30 นาที หรือก่อน cut-off ขนส่ง | ตั้งเงื่อนไข → ระบบปล่อยใบหยิบเข้าคิวตามรอบ | picking-auto |
| 3 | รถเข็นและตะกร้า | หัวหน้าคลัง | ทะเบียน cart/tote พร้อมบาร์โค้ด ผูกตะกร้ากับออเดอร์ตอนหยิบ และดูว่าใบไหนใช้อยู่ | ก่อนเริ่มหยิบ สแกนผูก cart/tote กับใบหยิบ → ใช้ต่อตอนคัดแยกและแพ็ค | picking-carts-totes |
| 4 | ใบหยิบ (Pick list) | พนักงานหยิบ, หัวหน้าคลัง | รายการใบหยิบและรายละเอียด ว่าต้องหยิบอะไร จาก location ไหน กี่ชิ้น หยิบไปแล้วเท่าไร | รับใบหยิบที่ถูกมอบหมาย → เปิดดูรายการ → เริ่มหยิบ | picking-lists, picking-list-detail |
| 4 | หยิบบน PDA | พนักงานหยิบ | PDA นำทางไปทีละ location พนักงานสแกน location และสินค้าเพื่อยืนยันว่าหยิบถูก | สแกนใบหยิบ → เดินตามลำดับ → สแกนยืนยันทีละรายการ → ปิดใบหยิบ | picking-pda-picking |

| 6 | แยกออเดอร์ (Sorting) | พนักงานคัดแยก | ถ้าหยิบแบบ batch (หลายออเดอร์รวมกัน) ต้องคัดของแยกเข้าช่องของแต่ละออเดอร์ก่อนแพ็ค | ของจาก batch pick มาถึง → สแกนสินค้า ระบบบอกช่องออเดอร์ → ครบแล้วส่งแพ็ค | picking-sorting |

| ขั้น | ฟีเจอร์ | ผู้ใช้หลัก | รายละเอียดฟีเจอร์ | User journey (มาจากไหน → ทำอะไร → ไปต่อที่ไหน) | ไฟล์ |
|---|---|---|---|---|---|
| 0 | ภาพรวมการแพ็ค | หัวหน้าคลัง | คิวงานแพ็ค จำนวนที่แพ็คแล้ว และผลงานรายสถานี/รายคน | ดูระหว่างกะ → ย้ายคนไปสถานีที่คิวยาว | packing, packing-jobs |
| 1 | เตรียมแพ็ค (Prep) | พนักงานแพ็ค | เตรียมกล่องและวัสดุไว้ก่อนตามออเดอร์ในคิว ลดเวลาที่สถานี ทำได้บนเว็บและ PDA | ดูคิวงานถัดไป → เบิกกล่อง/วัสดุตามที่ระบบจับคู่ไว้ → วางรอที่สถานี | packing-prep, packing-pda-prep |

### 7. ข้อสังเกตและจุดที่ควรตรวจต่อ

ระบบนี้ครอบคลุมกว่า WMS ทั่วไป เพราะรวมจัดซื้อ ขนส่ง (TMS เบื้องต้น) กำลังคน และ billing แบบ 3PL ไว้ในตัว

**จุดเด่นที่สังเกตได้**

- Multi-owner เต็มรูป: ทุกโมดูลแยกตามเจ้าของ มีอัตราค่าบริการเฉพาะลูกค้า และ Portal แยก
- คำขอ 2 ทาง: คลังส่งคำขอให้เจ้าของตัดสินใจ (owners-requests ↔ warehouse-requests) แทนการคุยผ่านแชท
- วงจรเคลมครบ: เคลม → ส่งซ้ำ → เบิก carrier → ชดเชยเจ้าของ → วิเคราะห์การป้องกัน
- วัสดุแพ็คเป็นสต็อกจริง: มีจับคู่วัสดุกับ SKU และแนะนำการสั่งซื้อจากอัตราใช้
- ควบคุมคุณภาพ: ล็อต/EXP, บันทึกอุณหภูมิ, สุ่มตรวจงาน, ทดสอบพนักงาน
- หน้าจอเฉพาะทาง: โหมดจอ TV, ตัวออกแบบ template เอกสาร, เครื่องมือปรับธีม, หน้าภาษาอังกฤษ (เฉพาะ overview)
