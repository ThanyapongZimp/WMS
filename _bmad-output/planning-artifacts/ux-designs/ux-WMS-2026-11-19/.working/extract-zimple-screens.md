# Extract: Zimple Fulfillment Screens (HTML prototype set)

Source: `artifact/Zimple Fulfillment Screens (Copy)/`. All paths below are relative to that folder.
Method: static reading + grep frequency counts across every `*.html` and `owner-portal/*.html`, with base64 images stripped first (about 29 MB of text). Nothing was executed.
Date of extraction: 2026-11-19.

---

## 0. What this set is

- `index.html` is a launcher with two entry cards:
  - "Zimple Fulfillment · ฝั่งคลัง", the warehouse-staff app, opening at `overview.html`.
  - "Client Portal · ฝั่งเจ้าของสินค้า", the owner portal, opening at `owner-portal/overview.html`.
- One prototype covers **two product editions plus optional modules**. A purple prototype-only bar (`.zvbar` / `.zvseg`, present in ~134 files, e.g. `overview.html`) switches between:
  - "Zimple Fulfillment (3PL)"
  - "Zimple WMS (Business)"
  - a "โมดูลเสริม" (add-on modules) checkbox
  Screens tag edition- or module-specific items with the badge "เฉพาะ 3PL" (`p-gray`, 142 uses) and the badge "เสริม" / "โมดูลเสริม · …" (`p-blue`).
- Theming is white-label at runtime, through `zwms-theme.js` (identical copy at `warehouse/zwms-theme.js`). The header says it is "generated by _design_scripts/build_theme_runtime.py, do not edit".
  - It recolours every hex in the page by **role family** (ink / primary / accent / muted / border / bg / success / warning / danger) and stores the choice in localStorage (`zwmsTheme`, `zwmsCompanyTheme`).
  - The default company theme is `MINE='Fullfeel Fulfillment'` (zwms-theme.js line ~332). "Zimple Fulfillment" is an indigo alternative preset.
  - `theme-tool.html` ("เครื่องมือ · ปรับธีมและสี") is the editor UI for these themes.
- Many screens are **annotated design specs**, not clean UI. They contain long inline rule text such as "หน้านี้เป็นตัวอย่างสำหรับดูการทำงานบน PDA เท่านั้น…" (`picking-pda-picking.html`). Nineteen files have a "แสดงหมายเหตุออกแบบ" (show design notes) toggle.

### 2.5 Framework and icons

- **No CSS framework.** A grep for tailwind, bootstrap, material, lucide, heroicons and fontawesome returned 0 hits. Everything is hand-written CSS that each file duplicates, plus many dated patch blocks such as `<style data-nw1105>`, `data-dc1108`, `data-rail1113` and `<script data-bw1108>`.
  - Per file: `overview.html` has 11 `<style>` / 7 `<script>` / 34 `!important`; `picking-pda-picking.html` has 12 / 7 / 64.
- **Interactivity is CSS-only.** It uses hidden checkbox/radio hacks: `.nt` for nav collapse, `#pAppr` / `#pNoti` for panels, `.drt` for drawers. A small JS `toast()` is injected by a patch script.
- **Icons:** inline SVG in Lucide/Feather style.
  - Markup: `viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"`. stroke-width 2 occurs 8,985 times; 2.2 and 2.4 are used for chevrons.
  - No icon font.
- **Charts:** inline SVG and CSS bars (`.seg` stacked bar, `.prog` 6px progress bar, `.legend`/`.dot`). No chart library.

## 5. PDA / handheld pattern

The pattern is the same in all 13 PDA files. Samples are drawn as phone frames side by side on a desktop page, with the full desktop shell still around them. The files hold 4 to 16 frames each (e.g. `inbound-pda-sample.html` 16, `packing-pda-prep.html` 14, `picking-pda-picking.html` 5).

- **Frame:** `.phone` 380px (a later patch sets 330px). It has a 10px `#12305e` bezel, radius 28, `#f6f9fc` background and the footer "by Zimple Solution" (`.phone::after`).
- **Top bar (`.top`):** dark ink `#12305e`, white 12px text, showing task name, worker name and clock. Example: "หยิบสินค้า สมชาย · 11:10". A later patch adds a "‹" back affordance.
- **Body (`.bd`):** padding 8–12px, gap 5–10px. A sticky search/scan field sits on top. Job cards (`.task`) and pills follow.
  - The subgrid menu (`[data-pdc="subgrid"]`) uses 3-column square tiles with a 30px icon and 11px label.
- **Big buttons (`.bigbtn`):** 44–46px tall, radius 12, 700 weight, flex 1 so they fill the row. The primary one is filled `#2e5fac`; done / finish is `#1d7f47`.
  - These buttons are **not** the 56px+ glove-friendly size, and one patch drops their font to 12px.
- **Flow is scan-first.**
  - "สแกนเลขอะไรก็ได้ ระบบเปิดงานที่ถูกต้องให้เอง" (scan any number and the system opens the right job) (`inbound-pda-sample.html`).
  - Picking flow: "เลือกงาน (ของฉัน / รอรับ) หรือสแกน QR ใบหยิบ → สแกนรถเข็น → ไปตามจุด → สแกนตำแหน่ง → สแกนสินค้า / ล็อต → ใส่ช่อง" (`picking-pda-picking.html`).
  - Job lists have filter tabs "ทั้งหมด 5 · ของฉัน 1 · รอรับ 4". Urgent jobs are pinned on top with "⚡".
  - Progress is shown as "จุดที่ 3/12 · 25/71 ชิ้น". The current location is shown large: "ตำแหน่ง A-03-02".
- **Feedback** is described in copy, not built as a component:
  - Errors: "สแกนผิดมีเสียงเตือนและจอแดง" (wrong scan gives an alarm sound and red screen) (`packing-pda-packing.html`, `pda-login-menu.html`).
  - Urgent work: "งานด่วนขึ้นบนสุด + เสียงแจ้ง".
  - Success: `.okline` green 13px/600 with a check, e.g. "ล็อต L2407 ตรงกับที่จัดสรร".
  - Yellow screen for blocked-but-not-error states: "ตัวอย่างจอเหลือง" (`packing-station.html`).
- **Offline:** a header strip "รอส่ง 2 รายการ · สัญญาณหลุด ส่งให้เองเมื่อกลับมา". There is no resend button: "ไม่มีปุ่มส่งซ้ำ" (`picking-pda-picking.html`).
- **Concurrency:** "ยอดเปลี่ยนแล้ว สแกนใหม่" (`picking-pda-picking.html`).
- **Login** (`pda-login-menu.html`):
  - Scan employee QR badge. Username and password is optional. PIN keypad (4 digits) is optional and off by default. There is no OTP on PDA.
  - Error states:
    - unknown badge (ไม่รู้จักบัตร)
    - day badge not registered (บัตรรายวันค้างคืน)
    - already logged in on another device (เข้าระบบ PDA เครื่องอื่นอยู่)
    - no PDA permission (ไม่มีสิทธิ์ใช้ PDA)
  - Also: screen lock that unlocks by badge rescan, and a warehouse picker for multi-warehouse accounts.
- **Device notes in copy:** "PDA ไม่มีกล้อง · งานนี้ไม่มีวิดีโอ ถ่ายรูปด้วย PDA ได้" (`inbound-pda-sample.html`).

## 6. Language and tone

- **The UI is Thai-first.** English appears only in:
  - codes and IDs (SO-, PK-, AS-, TM-, CL-, BG-, PS-)
  - brand and carrier names (Flash, Kerry, SPX, J&T, Grab, Shopee, LINE)
  - a few terms: "Serial" (93) vs "ซีเรียล" (5), "Excel", "Pickup", "Backorder", "COD", "Document Insert"
  - an English mirror only for the overview (`overview-en.html`)
- There is a language toggle "ไทย / English" in the user menu, and "ภาษาเริ่มต้น ไทย English" in `settings-company-brand.html`.
- Domain vocabulary is consistent:
  - เจ้าของสินค้า (owner/client)
  - ใบหยิบ (pick list)
  - ใบรับเข้าชั่วคราว (temp receipt)
  - ภาชนะ (container)
  - ตำแหน่งพักสินค้า (staging location)
  - งานเพิ่มเติม (VAS)
  - รหัสสินค้า (1,191 uses) rather than SKU (4)
  - Preferred spellings: "แพ็ค" (3,706) over "แพ็ก" (14), and "สต๊อก" (361) over "สต็อก" (1)
- **Tone** is operational, terse and imperative. It uses "·" as a separator heavily, "→" for flows and "=" for rules ("สแกน… = …"). The copy tells the worker the consequence and the next action.

## 7. Quality issues and inconsistencies (anti-patterns to avoid)

1. **Three brand names compete.**
   - Page titles read "Fullfeel Fulfillment · …" in every file.
   - The logo alt reads "FullFeel — Your order fulfillment." (153).
   - The index reads "Zimple Fulfillment".
   - The sidebar reads "ระบบบริหารคลังสินค้า by Zimple Solution".
   - The edition bar reads "Zimple WMS (Business)".
   - Counts: "Zimple WMS" 452, "Zimple Fulfillment" 470, "Fullfeel" 411 + "FullFeel" 309.
   - The theme JS rewrites titles at runtime (`rename()`).
   - Tenant brand and vendor brand need a clear rule.
2. **Mixed calendar eras.** Most dates use C.E. ("ส. 10 ต.ค. 2026", `overview.html`; "2026" ×971), but billing uses B.E. ("ก.ย. 2569", `billing-summary.html`; ×27). The setting to choose between them exists (`settings-company-brand.html`), but the prototype mixes both.
3. **Design notes are mixed into production UI copy.**
   - Long rule paragraphs sit inside cards and PDA frames, e.g. the price-visibility note in `orders-detail.html` and "หน้านี้เป็นตัวอย่าง… ไม่มีเมนูนี้ในระบบ" in the PDA files.
   - Only 19 files have a "แสดงหมายเหตุออกแบบ" toggle to hide them.
   - The prototype is hard to read as a real screen, and implementers may ship the notes.
4. **Patch-on-patch CSS.**
   - Every file inlines the full CSS (150–700 KB per HTML file; `settings-warehouse-rules.html` is 700 KB), plus 10–19 dated `<style data-*>` patch blocks and 34–64 `!important` rules.
   - Rules conflict:
     - `.bigbtn` is 46px/14px in one rule and forced to 44px/12px in another (`picking-pda-picking.html`).
     - `.phone` is 380px and also 330px.
     - `.drawer .dh` borders use both `#eef3f9` and `#e1e8f0`.
   - There is no single source of tokens. The real token source is `zwms-theme.js` `FAM`.
5. **Inconsistent status semantics.**
   - "รออนุมัติ" is amber in one place and grey ("รออนุมัติ 4") in another.
   - Danger red has two values (`#b8352a` vs `#b42318`).
   - "ด่วน" (urgent) is red while "เร่งด่วน" is amber.
   - The p-blue / p-sky / p-navy trio is hard to tell apart.
6. **Small type for warehouse floor use.**
   - 11px (3,635) and 10px (992) are common.
   - PDA tile labels are 11px and sub-labels 10px (`[data-pdc="subgrid"]` in `picking-pda-picking.html`). The PDA top bar is 12px.
   - PDA buttons at 44px are below a glove-friendly 56px target.
7. **No empty, loading or error-page components.** Lists are always full of sample data. Error feedback ("จอแดง", "จอเหลือง") is only described in prose, never drawn as a reusable full-screen state.
8. **Very wide tables** (13 columns, nowrap, in `billing-summary.html`) rely on horizontal scroll with no column priority or sticky first column.
9. **CSS-checkbox interactivity.** Drawers, panels and nav collapse use hidden inputs, so focus management, Esc-to-close and focus trap are mostly absent. Some `:focus-visible` outlines exist (`.tog`, `.hbtn`).
10. **Rich sidebar and header chrome repeated inside PDA sample pages.** PDA frames sit inside the full desktop shell, so the handheld context and the desktop context blur.
11. **The theme system is over-configurable.**
    - `DEF` exposes ~60 knobs (button style, tab style ×4 levels, pill style, sidebar style, tooltip shape…) and there are 10 presets (`zwms-theme.js`).
    - This signals unsettled visual decisions rather than a fixed system.
    - The prototype's authored sidebar changed from dark to white on 12 Nov, while the runtime `DEF.sideStyle` is still `'dark'`.

## 8. Reusable takeaways (observed, not invented)

- The role-based palette (`FAM`) with role-based theming is a clean base for white-label tenants.
- The IA shape "hub + document queues with counts" is consistent across modules.
- The scan-first station layout is a strong pattern: step strip, next-scan banner, requirement tiles, scanned/expected table, scan-command chips.
- PDA login and offline / concurrency messaging is detailed and worth keeping as behaviour spec.
- Edition and module tagging ("เฉพาะ 3PL", "เสริม") is a visible mechanism to carry into the IA.
